1. **P1 — Unauthenticated remote input:** [MainActivity.kt:207](/projects/kabuk/app/src/main/java/app/kabuk/MainActivity.kt:207). The activity is exported; another app can explicitly invoke `OPEN_AGENT` with fabricated `tab`, `pane`, `expect`, and arbitrary `reply`. Matching a predictable menu permits remote input without user approval. **Fix:** move answering into a non-exported activity, validate a private action token, and restrict replies to the expected choices.

2. **P1 — Old approval answers a different question:** [Herdr.kt:120](/projects/kabuk/app/src/main/java/app/kabuk/agents/Herdr.kt:120). Only truncated choice labels are compared. Two different commands commonly have identical approval menus, so a stale “Yes” approves the newer command. **Fix:** bind answers to an agent incarnation and unique question generation; include full question content rather than display labels.

3. **P1 — Check/send race and duplicate answers:** [Herdr.kt:117](/projects/kabuk/app/src/main/java/app/kabuk/agents/Herdr.kt:117). Reading and sending use separate SSH commands. Another client can answer between them; two rapid taps can also both validate before either sends. The extra answer reaches subsequent input. **Fix:** serialize/deduplicate local answers and implement server-side atomic question validation and consumption.

4. **P1 — PendingIntent silently changes question:** [AgentNotifier.kt:90](/projects/kabuk/app/src/main/java/app/kabuk/agents/AgentNotifier.kt:90). Every question in a pane reuses the same action identity with `FLAG_UPDATE_CURRENT`. Updating the notification changes the extras behind an older action, allowing a tap on the old question to answer the new one—even with different labels. **Fix:** give each connection/pane/question/action a unique intent data URI and invalidate old actions. [Android semantics](https://developer.android.com/reference/android/app/PendingIntent).

5. **P1 — Locked-phone approvals on Android 8–11:** [AgentNotifier.kt:109](/projects/kabuk/app/src/main/java/app/kabuk/agents/AgentNotifier.kt:109). Supported API levels 26–30 get broadcast answer buttons without authentication enforcement. When lock-screen actions are available, someone can approve remote operations while locked. **Fix:** route these versions through an activity requiring unlock before sending, or omit direct answer buttons. [Authentication API](https://developer.android.com/reference/android/app/Notification.Action.Builder.html).

6. **P1 — Rejection explanation reaches the wrong pane:** [AgentUi.kt:122](/projects/kabuk/app/src/main/java/app/kabuk/ui/AgentUi.kt:122), also [MainActivity.kt:202](/projects/kabuk/app/src/main/java/app/kabuk/MainActivity.kt:202). Focus runs asynchronously and its result is ignored; the prompt opens immediately. If focus fails or is slow, the explanation goes through the terminal to its previously focused agent. **Fix:** await successful answer/focus and bind explanation submission to the intended pane.

7. **P2 — Answer completion hides the next question:** [AgentNotifier.kt:126](/projects/kabuk/app/src/main/java/app/kabuk/agents/AgentNotifier.kt:126). A new question can be notified before the previous answer callback finishes. `answered()` then overwrites it with “Sent”; `notified` already records the new question, preventing reposting. **Fix:** replace a notification only if its question generation still matches the completed answer.
